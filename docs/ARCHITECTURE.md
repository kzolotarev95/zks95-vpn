# Архитектура

Все клиенты используют версионированный `/api/v1` FastAPI. PostgreSQL хранит состояние. Redis обеспечивает распределённые лимиты и очереди будущих фоновых задач. Next.js обслуживает публичный сайт и кабинет через nginx на одном origin.

Сессии — случайные отзываемые токены; в базе хранится SHA-256, в браузере HttpOnly cookie. Изменяющие запросы с cookie проверяют Origin. Для последующих служебных клиентов предусмотрен Bearer. Пароли хешируются Argon2id. Публичная регистрация не выдаёт права администратора.

Стоимость фиксируется в заказе целым числом копеек. Создание заказа не активирует доступ. Активацию выполняет только Billing после проверки подтверждённого платежа у провайдера. Платёжные события должны обрабатываться идемпотентно в транзакции. Конфигурации VPN создаются после активации и передаются через очередь команд агенту.

VPN-ноды не получают доступ к базе. Агент соединяется с API по HTTPS, принимает только подписанные команды из разрешённого набора. Адаптеры протоколов управляют конкретными службами без публичного shell API. VPN-ноды разворачиваются отдельно от control plane.

Не реализованные компоненты описываются в плане; фиктивные успешные платежи, VPN-конфигурации и статистика в рабочем API недопустимы.
